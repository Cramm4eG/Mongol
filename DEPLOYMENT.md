# Пошаговая инструкция по запуску  
«Контроль контрагентов»

Инструкция написана для человека, который раньше не разворачивал веб-приложения.  
Следуйте шагам строго по порядку.

---

## 1. Создание аккаунта и проекта в Supabase

1. Откройте сайт: [https://supabase.com](https://supabase.com)
2. Нажмите **Start your project** или **Sign in**.
3. Войдите через GitHub (рекомендуется) или по email.
4. После входа нажмите **New project**.
5. Заполните:
   - **Name** — любое название, например `counterparty-control`
   - **Database Password** — придумайте надёжный пароль и **обязательно сохраните его** (он понадобится редко, но восстановить сложно)
   - **Region** — выберите ближайший (например, `Southeast Asia (Singapore)` или `Central EU`)
6. Нажмите **Create new project**.
7. Подождите 1–2 минуты, пока проект создастся.

---

## 2. Получение URL и ключа

1. В левом меню нажмите на иконку шестерёнки **Project Settings**.
2. Перейдите в раздел **API**.
3. Найдите блок **Project URL** — скопируйте его (выглядит как `https://xxxxxxxx.supabase.co`).
4. Найдите блок **Project API keys** → ключ **anon** / **public**.  
   Скопируйте его (длинная строка, начинается обычно с `eyJ...`).

Эти два значения нужно будет вставить в файл `index.html`.

> **Важно:** ключ `service_role` (secret) **никогда** не вставляйте в код сайта. Он даёт полный доступ к базе.

---

## 3. Создание таблиц и настройка безопасности

1. В левом меню нажмите **SQL Editor**.
2. Нажмите **New query**.
3. Откройте файл `schema.sql` из этого проекта на компьютере.
4. Скопируйте **весь** текст файла и вставьте в окно SQL Editor.
5. Нажмите кнопку **Run** (или Ctrl+Enter).
6. Должно появиться сообщение об успешном выполнении (зелёная галочка).  
   Если есть ошибки — пришлите текст ошибки.

---

## 4. Включение Realtime

1. В левом меню откройте **Database** → **Replication** (или **Publications**).
2. Найдите таблицу `counterparties` и включите для неё Realtime (переключатель).
3. То же самое сделайте для таблицы `audit_log`.

Если переключателей нет — в SQL Editor выполните:

```sql
ALTER PUBLICATION supabase_realtime ADD TABLE public.counterparties;
ALTER PUBLICATION supabase_realtime ADD TABLE public.audit_log;
```

---

## 5. Создание двух пользователей

1. В левом меню откройте **Authentication** → **Users**.
2. Нажмите **Add user** → **Create new user**.
3. Заполните:
   - Email сотрудника № 1
   - Пароль (минимум 6 символов)
   - Поставьте галочку **Auto Confirm User** (чтобы не нужно было подтверждать почту)
4. Нажмите **Create user**.
5. Повторите для сотрудника № 2.

Запишите email и пароли — они понадобятся для входа в приложение.

---

## 6. Отключение публичной регистрации

1. В разделе **Authentication** откройте **Providers**.
2. Найдите **Email** и нажмите на него.
3. Отключите переключатель **Enable sign ups** (или **Confirm email** + запрет регистрации — главное, чтобы новые пользователи не могли сами регистрироваться).
4. Сохраните изменения (**Save**).

Теперь зарегистрироваться сможет только тот, кого вы создали вручную.

---

## 7. Вставка ключей в код

1. Откройте файл `index.html` в любом текстовом редакторе (Блокнот, VS Code, Notepad++ и т.д.).
2. Найдите в самом конце файла (перед `</body>`) вот этот блок:

```html
<script>
  window.SUPABASE_URL = 'https://YOUR_PROJECT_REF.supabase.co';
  window.SUPABASE_ANON_KEY = 'YOUR_ANON_KEY_HERE';
</script>
```

3. Замените:
   - `https://YOUR_PROJECT_REF.supabase.co` → ваш Project URL
   - `YOUR_ANON_KEY_HERE` → ваш anon key

4. Сохраните файл.

---

## 8. Проверка работы локально (по желанию)

1. Откройте файл `index.html` двойным кликом в браузере.
2. Должен появиться экран входа.
3. Войдите одним из созданных пользователей.
4. Если всё настроено правильно — вы увидите пустой список и кнопку «+ Добавить контрагента».

Если появляется сообщение «Настройка не завершена» — значит, вы забыли заменить URL или ключ.

---

## 9. Публикация на Cloudflare Pages

### Вариант А (рекомендуется) — через GitHub

1. Создайте аккаунт на [GitHub](https://github.com), если его нет.
2. Создайте новый репозиторий (New repository), название любое, например `counterparty-control`.  
   **Не** ставьте галочку «Add a README».
3. Загрузите в репозиторий все файлы проекта (`index.html`, `styles.css`, `app.js` и остальные).
   - Можно через сайт GitHub: кнопка **Add file** → **Upload files**.
4. Зайдите на [https://pages.cloudflare.com](https://pages.cloudflare.com) или в [Cloudflare Dashboard](https://dash.cloudflare.com) → **Workers & Pages**.
5. Нажмите **Create application** → **Pages** → **Connect to Git**.
6. Подключите GitHub и выберите репозиторий.
7. Настройки сборки:
   - Framework preset: **None**
   - Build command: оставьте пустым
   - Build output directory: `/` (или `.`)
8. Нажмите **Save and Deploy**.
9. Через 1–2 минуты сайт будет готов. Cloudflare выдаст адрес вида `https://название.pages.dev`.

### Вариант Б — прямая загрузка (без GitHub)

1. В Cloudflare Dashboard → **Workers & Pages** → **Create** → **Pages** → **Upload assets**.
2. Перетащите папку с файлами проекта или выберите файлы.
3. Нажмите **Deploy site**.

---

## 10. Открытие сайта на компьютере и телефоне

1. Скопируйте адрес, который выдал Cloudflare (например `https://counterparty-control.pages.dev`).
2. Откройте его в браузере на компьютере.
3. На телефоне откройте тот же адрес в Chrome / Safari.
4. Можно добавить сайт на главный экран телефона (в браузере: «Добавить на главный экран») — будет выглядеть почти как приложение.

---

## 11. Проверка работы двумя сотрудниками

1. Сотрудник 1 входит с компьютера.
2. Сотрудник 2 входит с телефона (другой email).
3. Сотрудник 1 добавляет контрагента → у сотрудника 2 он появляется **без обновления страницы**.
4. Сотрудник 1 меняет статус на «Запрещён» → у сотрудника 2 статус сразу становится красным.
5. Откройте «История действий» — должна появиться запись с email и временем.

---

## 12. Проверка безопасности

1. Выйдите из аккаунта.
2. Попробуйте открыть сайт — должен быть только экран входа.
3. Попробуйте зарегистрировать нового пользователя (если кнопка регистрации есть — её не должно быть).
4. Без входа нельзя увидеть список и историю.

---

## 13. Что делать при ошибках

| Проблема | Что проверить |
|----------|---------------|
| «Настройка не завершена» | Не заменены URL и ключ в `index.html` |
| Неверный email или пароль | Пользователь создан? Auto Confirm включён? |
| Данные не синхронизируются | Realtime включён для обеих таблиц? |
| Ошибка при добавлении | Выполнен ли `schema.sql` полностью? |
| Проект «уснул» | В Supabase Dashboard нажмите **Restore** (бывает после недели неактивности) |
| Белый экран | Откройте консоль браузера (F12) и посмотрите ошибки |

---

## 14. Полезные советы

- Пароли сотрудников можно менять в Supabase → Authentication → Users.
- Чтобы добавить третьего сотрудника — просто создайте ещё одного пользователя в Authentication.
- Архивированные контрагенты не показываются в списке, но их история остаётся.
- Все времена в истории отображаются по часовому поясу **Asia/Bishkek**.
